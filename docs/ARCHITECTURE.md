# 一个 benchmark，两个 CAD 后端

更新：2026-10-16。**已确定保留同一个仓库，SolidWorks 与 FreeCAD 分别作为 CAD 后端。共用案例、任务规则、结果格式和评测政策，各自维护 CAD 操作、原生文档与运行环境。**

同仓库不要求同机安装两套 CAD。SolidWorks 本地 Case 13 流程已跑通；FreeCAD 尚未完成本项目端到端验收。此处新增目录是文档入口，不是可执行后端已经发布。

| 模块 | 负责什么 | 本次发布状态 |
|---|---|---|
| cases/ | 案例编号、源文件、来源和哈希 | 六例源数据已存在；注册就绪状态不提升 |
| runner/ | 准备任务、限制预算、分离工作区、收卷、记录 | 发布职责说明；Case 13 控制器代码仍在本地 |
| agents/codex_cli/ | 接入 Codex CLI，由 CLI 组织模型与工具循环 | 发布本地试验协议说明 |
| backends/solidworks/ | Windows CAD 调用、原生图纸、DXF 导出、状态提取 | 发布已跑通范围与待迁移清单 |

## 2. 从输入到结果

1. 控制程序给出图任务准备 STEP、公开任务说明、工具说明和可写目录。
2. 出图 AI 用 Python 和 CAD 工具检查几何、创建视图、标注、渲染预览并修改。
3. SolidWorks 试验中，AI 保存原生工程图并写提交标记；CLI 结束后，控制程序重开原生图纸，导出最终 DXF、提取 JSON，再渲染 DXF 预览。
4. 控制程序启动独立重建会话，只提供最终 DXF、由它生成的 PNG 和通用说明。
5. 重建 AI 保存 STEP 并提交。评测器才读取原 STEP，计算几何 IoU；剖切与碰撞检查分别报告。
6. 控制程序汇总时间、token、尝试次数、失败原因和成本估算。GT 分数不回传本轮两个 AI。

JSON 表示 CAD 最终状态，不由 AI 口述提供。原生状态提取与通用日志接口是两层实现：本地试验直接读取原生图纸，仓库日志接口尚未接上真实 CAD 适配器。

## 3. 两套后端共享什么、分别实现什么

| 共享 | 分别实现 |
|---|---|
| 同一输入 STEP 及哈希、单位 | SolidWorks / FreeCAD 版本和安装方法 |
| 任务目标、公开工具规则、预算口径 | CAD API、视图和标注帮助函数 |
| 最终 DXF、预览和派生状态的语义 | .SLDDRW / .FCStd 保存、重开和导出 |
| 独立重建输入边界、IoU 政策 | 坐标变换、剖切状态提取、成功操作记录 |
| 用量、时间、失败类别和报告字段 | 操作系统权限、进程资源控制、隔离验收 |

依赖按后端安装；运行一套后端不应强制安装另一套。功能缺失必须报告 unsupported，不将复杂剖法悄悄降级成普通全剖。共同接口先固定职责与语义，具体 Python 函数签名待真实后端适配后冻结。

## 4. 按案例和运行保存产物

下面是后续统一目录；不迁移既有源文件，也不冒充当前 Case 13 已按此结构运行：

```text
cases/case_NNN/                   公开源清单与已登记材料
runs/case_NNN/<backend>/<run_id>/  本地运行根目录，不整体提交 Git
  config.json                    模型、CAD、预算、工具与指标版本
  drawing/
    input/                       出图 AI 输入
    work/                        出图代码和中间产物
    output/frozen/               收卷后的原生图纸、DXF、JSON、PNG
  reconstruction/
    input/                       只有最终 DXF 和 PNG
    work/                        重建代码与中间产物
    output/                      重建 STEP、假设、提交标记
  controller/                    原始事件、CAD 请求、快照、交接哈希
  evaluation/                    IoU 与其他检查结果
  report/                        人工报告和机器可读摘要
```

私有 GT 存放在评测环境的受限数据根目录，不提供给 Agent。即使工作树含有公开的 SLDPRT 源材料，出图任务也只获得明确允许的 STEP 输入；不能直接开放整个仓库。目录名本身不构成隔离。

已存在的 Case 13 使用独立试验根目录，其中评测目录名为 `evaluator/`。其原始路径与记录保留；统一目录迁移属于后续代码工作。

## 5. 比较实验与迁移顺序

结果必须注明 backend、CAD 版本、工具集、模型、预算和指标版本。相同模型在不同 CAD 后端运行是不同条件，先分组报告；不能把工具能力差异都解释为模型能力。

1. 整理并公开公共协议、SolidWorks 已测状态、FreeCAD 计划和本地试验摘要。
2. 单独迁移 SolidWorks 控制器，去除机器绑定配置，并做隔离和重开／导出验收。
3. FreeCAD 先验证 STEP 导入、普通投影、直线全剖、关联尺寸、DXF 和预览，再接最终状态提取。
4. 用相同案例验证两个后端的共同能力范围，随后开展可比较运行。

本次只完成第一步的文档发布，不新跑模型，不安装 CAD，不发布本地机器设置。
