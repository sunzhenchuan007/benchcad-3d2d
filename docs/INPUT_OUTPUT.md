# 输入、输出与交互协议

**出图 AI 读 STEP，通过 CAD 工具制图；控制程序从提交的原生图纸生成最终 DXF、预览和实际状态 JSON。重建 AI 只读最终 DXF 和它的预览，提交 STEP。**

这是已测 SolidWorks 试验与两个后端目标协议的对照。FreeCAD 适配和正式统一 schema 尚未冻结；不能把目标目录或示例字段视作已可执行接口。

## 1. 文件可见性

| 内容 | 出图 AI | 重建 AI | 控制程序／评测器 |
|---|---|---|---|
| 任务说明、公开工具和预算 | 可读 | 可读其阶段版本 | 管理 |
| 原始输入 STEP | 可读 | 不可读 | 可读 |
| 中性原生缓存 | Case 13 明确提供 | 不可读 | 从同一 STEP 转换 |
| 自己的代码和工作产物 | 可读写 | 可读写自己的目录 | 收集与审计 |
| 最终 DXF、其 PNG | 由收卷程序生成 | 可读 | 冻结并记录哈希 |
| 原生工程图 | 生成与保存 | 不提供 | 重开、导出、提取状态 |
| 派生 drawing.json、出图日志 | 不作为 GT 反馈 | 不提供 | 可读 |
| 专家 DXF、私有 GT、原生设计树 | 不提供 | 不提供 | 依评分职责可读 |
| 最终分数 | 本轮不提供 | 本轮不提供 | 写报告 |

对同一阶段，模型保留完成任务必要的上下文；独立案例、重复试验和两类 AI 任务之间开启新会话。禁止访问的目录需要实际权限与工具入口检查，不只写在提示词中。

## 2. 一轮交互是什么

控制程序启动 CLI，CLI 将任务与工具定义交给模型。模型可以请求读文件、执行代码、查看图片，或结束答复。CLI 执行工具后将结果加入上下文，再请求模型。外部控制程序检查总时间与进程限制。

运行 Python 返回 stdout、stderr、退出状态或运行中状态；生成 PNG 只得到文件，模型还需要看图工具才能得到视觉输入。CAD 执行返回错误可供模型修改，但不返回隐藏 GT 分数。

当前没有 30 个模型决策轮的硬上限。CLI 启动、模型响应、shell 调用、CAD 请求和最终提交分开统计。总时间预算内允许反复自查，最终每阶段接收一个结果。准确计数与限制见 [详细指南](AGENT_SOLIDWORKS_CODEX.md)。

## 3. SolidWorks 已测收卷流程

| 文件 | 谁生成 | 用途 |
|---|---|---|
| output/drawing.SLDDRW | 出图 AI 请求 CAD 工具保存 | 原生工程图 |
| output/SUBMIT.json | 出图 AI 写入 | 内容为 {"native":"drawing.SLDDRW"} 的提交请求 |
| output/frozen/drawing.dxf | 控制程序重开原生图纸并调用 CAD 导出 | 最终二维评测产物 |
| output/frozen/drawing.json | 控制程序读取同一原生图纸 | 实际视图、变换和剖切状态，不是 AI 自报答案 |
| output/frozen/preview.png | 控制程序渲染最终 DXF | 重建 AI 的图片输入 |
| reconstruction/output/model.step | 重建 AI 请求建模工具保存 | 重建三维模型 |
| reconstruction/output/SUBMIT.json | 重建 AI 写入 | 内容为 {"step":"model.step"} 的提交请求 |

AI 在工作中导出的自查 DXF 不直接替代控制程序收卷导出的最终 DXF。写 SUBMIT.json 后由 AI 结束；当前控制程序等 CLI 退出后处理，标记首次出现时尚不即时锁定。聊天说“完成”不等于文件验收通过。

FreeCAD 计划提交 .FCStd 并经对应适配器导出相同语义的产物；实际提交字段须在实现时版本化，当前没有可用 FreeCAD 提交命令。

## 4. 实际状态 JSON 与 GT JSON

派生状态至少需要 case/run 身份、输入 STEP 哈希、单位、坐标约定、最终文件哈希、视图变换、剖视类型、实际切面定义和图纸证据引用。派生字段取自成功操作及最终原生状态；模型聊天文本不能证明操作成功或视图仍然存在。

GT 记录要求：固定 STEP 和轴线引用、contains_axis 或 crosses_axis_at_station、容差、可选角度、必要／可选／替代关系。网页草稿不等于批准的 GT。不同 GT 版本先迁移和校验，再评分。

DXF handle 只定位同一份图纸中的图元，不与专家图纸 handle 作身份匹配。整体镜像 IoU 允许的变换，不自动改写剖切 GT 坐标或放宽剖切规则。

[公共日志接口](OPERATION_LOG_DERIVATION.md) 消费规范 JSONL，绑定导出哈希并归约最终状态。目前它与本地直接读取 CAD 的提取器尚未接通；日志状态为 derived 也不表示实际 DXF 证据已核验或得分合格。

## 5. 结果和存储

各运行记录模型／CAD／工具版本、提示词标识、输入及产物哈希、预算、阶段耗时、工具与 CAD 次数、token、失败类型、指标版本、采用 IoU、原旋转 IoU、镜像标记及分项状态。缺项保留 null 或明确未评测，不能填零冒充已测。

输入 token 包含缓存 token；按价格折算时普通输入与缓存输入分开计价，推理 token 不重复加到已包含它的输出中。费用标为估算，与账户实际费用分开；只有阶段汇总 usage 时不能推断每次请求的价格档位。

原始日志、代码快照与机器配置保留本地；公开报告采用经过检查的摘要。目标目录见 [架构](ARCHITECTURE.md)，源清单沿用 [CASE_SPEC.md](CASE_SPEC.md)，本次不改变源文件或注册状态。
