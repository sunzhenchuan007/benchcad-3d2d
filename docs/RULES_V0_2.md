# 开发版规则 development-v0.2

本页定义可运行框架的规则。权重和罚分未做专家校准，**可以修改，不是正式冻结指标**。
机器配置：[rules.v0.2.json](../config/rules.v0.2.json)。每份报告记录规则 ID 与内容 SHA-256；修改配置会产生不同指纹。

## 输入与 GT 边界

| 规则 | 约定 |
| --- | --- |
| I01 | 模型输入选定 STEP；原生 SLDPRT、CQ 元数据、GT 和内部实体映射不提供给模型。 |
| I02 | GT 具有独立版本，保存必需参数、结构、固定基准及证据绑定。不能把目标参数写进固定基准表。 |
| I03 | 已实现原生显示尺寸和特征类型的只读记录，并审核 Case 84 参数化；通用原生语义提取未完成，导入体不自动等于有可提取原生孔特征。 |
| I04 | 受控 CQ 构造可以共用参数生成模型和 GT，必须核对导出再导入后的最终几何。 |
| I05 | 无尺寸参考剖视图可用于规划表达要求；切面不能唯一确定时须补定位。examples 是独立合成说明；Case 84 的开发就绪状态由其原生配对和重建证据决定。 |
| I06 | 第一版只支持 mm 和固定坐标框架。单位不一致、重复 ID、非有限数字、错误版本直接拒绝。 |

## 信息完整性

Case 84 的受控 `structure_note` 将实际可见的结构说明与指定中心线核验后，转为后台规范化的轮廓过渡/居中要求；仍不能仅从 JSON 声明加入结构信息。这是受控文本词表扩展，不是任意注释的自然语言识别。

| 规则 | 约定 |
| --- | --- |
| D01 | GT 真值只用于核验，不能作为图纸已表达的方程；预测 features 中的数字也不能替代尺寸。 |
| D02 | 关系系统仅包含实际有效的尺寸、符号和结构标注。仅 JSON 输入属于 relations-only 诊断，不能判整图通过。 |
| D03 | 接受等价尺寸链，不要求方程、矩阵或历史节点逐项相同。 |
| D04 | 分别报告 determined、missing、wrong、inconsistent；确定但错误不能算完整。 |
| D05 | 检查每个参数的唯一性，而不只检查总秩。未锚定连通分量可以有内部关系，但仍欠约束。 |
| D06 | 矛盾按约束分量报告，独立的 Y 分量不因 X 分量冲突而失去诊断。 |
| D07 | 通孔/盲孔等离散结构单独检查，不能用连续矩阵秩代替。 |
| D08 | 不支持的约束、未绑定实体或拒绝的标注显式报告，并阻止完整通过。 |
| D09 | 一个工程标注可以展开多条标量约束；各矩阵行保留原始标注 ID，报告汇总参与依赖的标注集合。 |
| D10 | 缺失、矛盾、冗余分别诊断，可以同时出现。全矩阵秩和左零空间分析不依赖添加顺序，不逐项删除。 |
| D11 | 对定位可靠、实际可见的尺寸数值另建名义约束诊断；56 与 60 的冲突不能因 60 不符合几何而被静默丢弃。拒绝的标注不计完整性，冲突分量也不计正确参数。 |
| D12 | 单独按系数系统检查欠约束；即使同一分量矛盾，也保留缺失自由度诊断。不能用矛盾覆盖缺失。 |

支持的线性 IR：有向轴向差值、长度、直径、深度、半径转直径，以及显式线性方程。
受控 DXF 的对称、对齐和 2X 相同孔说明，经实际图面证据验证后展开线性关系。
任意角度、欧氏距离、多解非线性、GD&T 和未知符号均未实现，不能默认通过。

## 图纸证据与剖切

| 规则 | 约定 |
| --- | --- |
| V01 | 普通正投影视图不要求剖切标记。需要标记的剖视图须在 Case 表达合同中列出。 |
| V02 | 读取插入到图面的实际视图、DIMENSION、线段、圆、箭头实体和 TEXT；不能只相信预测 JSON。 |
| V03 | 尺寸数值、测量方向、两端锚点、所属视图、DIMENSION 文本和实际匿名块显示标签必须一致；隐藏尺寸及非单位 dimlfac 显式拒绝。 |
| V04 | 剖切位置线、箭头、编号和对应剖视标题分别检查；JSON 正确而图面缺失仍扣分。 |
| V05 | 剖面轮廓、孔的俯视圆和剖面线另行检查。剖切标记正确不保证轮廓正确。 |
| V06 | 切面声明、实际位置线和预期剖面应对应。当前只实现受控 Y 法向全剖模板。 |
| V07 | 实际绘出的尺寸若未被绑定并验证，不得藏在 JSON 之外，按未支持证据处理。 |
| V08 | controlled-dxf/0.1 只支持命名 VIEW_* 块、平移插入、规定的线型/图层/文本和几何绑定；旋转缩放或未知表示显式拒绝。它不是通用 DXF/SLDDRW 解析器。 |

剖切标记预算为每个剖视图 10 分（内部预算，不直接等于总分罚分）：

| 缺陷 | 内部扣分 |
| --- | ---: |
| 缺少剖切位置线 | 10，结束本视图的标记检查，避免继续重复扣分 |
| 位置线错误 | 4 |
| 箭头缺失或错误 | 2 |
| 编号缺失或错误 | 2 |
| 标题不对应 | 2 |

预算上限与各罚分由配置定义。当前受控模板规定了编号/标题和锚点；任意同义文本、任意布局和标准允许的省略情况尚未自动解析，应通过后续 Case/适配器版本明确支持。

## 评分、硬门槛与效率

沿用仓库初始大项权重：F=40%、D=35%、V=20%、E=5%。

- **F**：当前为类型、位置、轴向、参数签名的最大一对一匹配 F1；预测 ID 可不同，多报特征会降低精确率。DESIGN.md 中更细的参数/关系分项仍是后续扩展。
- **D**：正确且唯一确定的必需连续参数，加已表达的必需结构条件，除以总要求数。
- **V**：对必需视图取均值。普通视图检查几何；剖视图默认一半检查轮廓和切面、一半检查剖切标记。此拆分可配置。
- **V 的遮挡修正**：每个视图的基础 V 再乘可读性系数。实际文字框互相碰撞或被 LINE 几何穿过，每对对象扣内部 2 分，上限 10 分，间距 0.3 mm；同对对象去重，单纯尺寸线交叉不直接扣。当前仅受控向量视图，非完整制图标准检查。遮挡不改变 D 中数值的正确性，但阻止整图通过。
- **E**：完整通过后才计分。rank(A)/m × min(1,参考视图数/实际视图数)，其中 m 是实际核验的标量约束行数。一致情况下 m−rank(A) 为独立重复量。没有“哪项新增”的责任假设，报告列出全部依赖参与项；多条路径的组合不重复计罚。缺失时 E=0，但继续报告依赖。

S = 100 × (0.40F + 0.35D + 0.20V + 0.05E)。

完整通过须同时满足特征、连续与离散信息、图纸证据、视图及标记要求，并无拒绝项/未支持项。总分高不能替代硬门槛。
整图 complete 只覆盖 GT 声明的参数/结构/模板范围，不代表任意复杂工程图或全部制造标准已被验证。

例如两视图的双孔样例：缺少剖切线时，俯视图 V=1、剖视图 V=0.5，V 均值=0.75；再因不完整失去 E，最终得 90 分。

## 防止声明替代绘图

JSON 是证据索引，不是图纸已表达信息的证明。按实际插入视图、可见文字、几何锚点和符号核验后才接受标注；缺失、隐藏、引用复用或未知尺寸不能通过。仅 JSON 的关系分析不给总分。

报告新增 `annotation_evidence.verified_claim_fraction` = 已核验标注声明数 / 提交的尺寸与结构标注声明数（无声明或未核验图纸时为 null）。这是可诊断的证据一致性比例，不单独加权，以免重复扣分；完整通过还须无拒绝/未知项，比例 100% 本身不能证明尺寸齐全。

`drawn_nominal_diagnostics` 保留真实显示数字的冲突证明及系数/增广秩；`dependency_diagnostics` 保存左零空间依赖证据；`underdetermined_required_variables` 保存欠约束信息；指纹及 `verifier_revision` 记录实际核验对象。当前修订为 development-v0.2，规则及报告 schema 升至 /0.2；GT/prediction 仍是 /0.1。开发版字段结构尚未冻结。

当前只验证受控向量 DXF，尚不支持任意 PNG/PDF 的 OCR、通用 SLDDRW、完整遮挡及排版可读性。一般工程图建议由可信导出器同步生成图纸和证据，再独立核验实际渲染；这属于后续适配器工作，不能声称已完全防止伪造。

本例按 Case 约定把沉孔 Ø16 和小孔 Ø10 放在同一剖视图的两个标注层次，并把深度 6 移到剖面轮廓外。并非声明所有沉孔都必须只能标在剖视图；通用规范及合理参考尺寸需单独定义。

## 容差与版本

- 几何绑定及 GT 数值绝对容差：0.1 mm；相对容差：1e-6。
- 切面法向夹角容差：1°，按归一化法向的实际夹角检查，不分别判断分量。
- 名义线性关系的一致性容差：1e-6 mm，与 GT 测量容差分开，不冒充制造公差区间求解。
- 系数使用 Fraction 消元，按每个参数是否依赖自由变量判断唯一性；报告保留实际标注证明路径和冲突来源。
- 冗余诊断使用已安装 NumPy 的 LAPACK SVD；相对秩阈值 1e-12，先按行归一化，不使用几何测量容差当作秩阈值。若数值秩与精确系数秩不一致，明确阻止通过。
- 当前规模上限：128 个参数、512 个标注。第一版用于小规模开发，不能据此承诺大规模性能。
- 修改规则内容必须保留新指纹；修改字段语义、单位或求解支持范围应升级 schema/适配器版本并更新回归样例。
