# BenchCAD 三维到二维工程图评测方案

更新日期：2026-10-12。本文为当前方案；旧尺寸链路线保留在 Git 历史和历史说明中。总分权重、容差及正式提交 schema 仍待校准和冻结。

## 01 输入输出规范

### 输入：标准化 STEP 文件

出图 AI 接收零件的标准化 STEP 实体，以及统一的单位、坐标系和公开工具说明。标准化应保留真实尺寸，并记录输入文件 SHA-256；不得为了对齐而把大小不同的零件分别缩放成同一个单位体。

环境可以提供由同一 STEP 计算的面、边、轴线等中性几何引用。原生 SLDPRT、人工剖切 GT、专家 DXF 和评分参考信息不提供给出图 AI。原生文件可以留作数据来源记录，但不再要求先提取完整尺寸链才能开展评测。

### 输出：DXF 文件和 JSON 文件

- **DXF** 是实际工程图，必须清楚表达原零件的外形、孔、台阶、腔体等已有特征，并给出必要的尺寸和剖视。孔的数量、孔径、位置及通孔／盲孔等结构应在图纸中可辨识。
- **JSON** 主要记录实际剖切定义及其与图纸视图的关联，包括剖切面的位置、方向、剖视类型、所属视图和图纸证据引用。
- 剖视采用规范的剖切线、标识和必要箭头等表达。JSON 声明不能替代 DXF 中实际存在的剖视或标注。

这里的“包含剖切和打孔等特征”是要求图纸正确表达 STEP 中已有结构，不是要求 AI 修改原零件或凭空新增孔。哪些剖视必须出现，由各 case 的人工 GT 规定；不要求所有零件都强行增加剖视。

输入、GT 和提交的建议目录见 [INPUT_OUTPUT.md](INPUT_OUTPUT.md)。

## 02 评测与打分机制

### A. AI 根据 DXF 三维重建，比较体积 IoU

不再使用尺寸链、约束矩阵、秩分析或逐项标注推导作为本路线的图纸完整性验证。采用独立的验证 AI 从二维图纸恢复三维实体：

```text
标准化 STEP → 出图 AI → DXF + 剖切 JSON
                          │          │
                          │          └→ 与人工剖切 GT 比较
                          ├→ DXF 标注碰撞检查
                          └→ 独立验证 AI → 重构 STEP → 与参考 STEP 比较 IoU
```

验证 AI 只能读取提交的 DXF 和通用单位／工具说明，不得读取原输入 STEP、参考 STEP、原生 CAD、人工 GT 或提交 JSON。应通过实际文件访问隔离落实这一边界；仅在提示词中要求“不看答案”不足以实现隔离。

设重构实体为 R、参考实体为 G：

**IoU = Volume(R ∩ G) / Volume(R ∪ G)**。

参考几何来自选定的标准化 STEP。脚本读取重构 STEP，检查文件可解析且实体有效，再计算 IoU。比较保留绝对尺度；平移和旋转对齐策略、体素分辨率或布尔体积算法需要固定并公开。

IoU 作为几何恢复的主要分数，反映图纸能否支持恢复原零件。漏孔、错误孔深和缺失腔体会通过体积差异影响结果，但小孔和薄壁可能对整体体积贡献较小，因此 IoU 不单独证明所有工程表达都规范。

### B. 剖切面经过关键轴线的位置检查

人工 GT 标注需要表达的关键轴线及剖切位置要求。按具体目标选择两种规则：

| 规则 | 合格条件 |
| --- | --- |
| 沿轴剖 `contains_axis` | 切面包含目标轴线；只在某一点与轴相交不算通过 |
| 横向剖 `crosses_axis_at_station` | 切面与目标轴的交点落在指定轴向位置及允许误差区间内 |

沿轴剖同时检查轴线方向与切面平行，以及轴线到切面的偏移。横向剖检查轴向交点；与轴平行、没有唯一横切交点的平面不能通过该规则。这些条件用于判断位置关系。

每条目标可选择：

- **不要求角度**：满足位置规则即可，允许不同的绕轴切面角度。
- **要求角度**：同时检查切面法向与指定参考法向的夹角误差。法向正反表示同一个平面，不因此扣分；观察方向和剖切箭头方向不由这一检查替代。

剖切目标建议分为“必要项”和“推荐项”：必要项缺失或位置错误扣分；推荐项符合要求可加分，未采用不判失败。同一个目标被重复满足不重复奖励。分类和加扣分权重仍待正式接口和评分器实现。

全剖、半剖可以作为合法表达方式。适当的全剖加外形视图可能与半剖提供等价的信息，不强制复制专家的剖法、视图位置或布局。半剖对部分对称零件更合适，但不能仅因局部曲面有轴线就认定整个零件对称。

专业剖切检查首先评价必要位置要求；经过轴线本身不保证内部特征已经显示完整。JSON 与实际 DXF 的剖视、剖切线及标识之间仍需建立证据对应，防止只在 JSON 中宣称已经剖切。

### C. DXF 标注碰撞与视图冗余

采用脚本读取 DXF 的文字、尺寸线、引出线、箭头等几何信息，检查影响阅读的重叠或遮挡。扣分应对应可定位的图纸问题，而不是只因两个包围框相交就判错；正常附着、尺寸界线接触和允许的交汇需要区分。

同一尺寸放在不同视图上，只要信息正确、表达清楚，不因它与专家的位置不同而扣分。视图数量可参考对应 T1 专家图纸：满足表达要求且数量不超过专家时，该项不扣分；超过时按预先公布的冗余规则扣分。PDF 识别保留适配接口，暂不作为主要实现。

正式报告分别给出几何 IoU、剖切位置结果和标注质量问题。总分组合、推荐项奖励、视图冗余扣分及阈值尚未冻结，不沿用旧方案的 40/35/20/5 权重。

## 03 GT 标注工作台

[剖切标注工作台](https://2d.cuptlab.site) 用于人工建立剖切位置 GT。交互包括六个标准视角、轴线／圆心点选、鼠标吸附高亮、位置规则和可选角度要求。姓名在当前浏览器中记忆，并可通过“下一个 case”连续标注。

JSON 草稿保存 STEP 哈希、稳定轴引用、位置容差及角度规则；完整支持面指纹留在配套几何索引中。界面中的 AX、F、E 短编号只用于当前页面查找，不作为跨文件的公共身份，AI DXF 中的 handle 也不与专家图纸 handle 作一一比较。

草稿需要正式验收后才能成为评分 GT。已有网页能够标注和导出，并不表示 AI 重建、图纸证据匹配或总分已经全部接通。

## 04 校准与实施边界

先使用可信的专家 DXF 检查验证 AI 是否能够稳定重建，再评测出图 AI。记录重建模型／提示词版本、工具环境和运行预算。专家图纸也重建失败时，应检查验证环节；不能把所有失败都直接归因于出图 AI。

提交缺失、无效重构实体、验证 AI 的重构不确定性和基础设施失败应分别报告。重试次数、失败计分方式和多次重构的聚合规则需要提前冻结，不能看完结果后挑选有利规则。

实施顺序：

1. 明确 DXF 与剖切 JSON 的正式提交接口和输入隔离。
2. 建立必要／推荐剖切 GT，补齐 JSON 与实际图纸的证据对应。
3. 校准专家 DXF 的 AI 重构可靠性，再进行模型生成图纸的对照试验。
4. 接通重构 STEP 的 IoU、DXF 碰撞和剖切匹配报告。
5. 用正确图纸、漏孔／错孔深、错误剖切、标注碰撞和冗余视图等对照样本校准扣分，最后冻结总分规则。
